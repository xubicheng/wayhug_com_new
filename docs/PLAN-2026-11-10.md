## 3. 读书笔记提交

### 3.1 为什么入库，不走邮件

邮件方案会把九个字段拍平成一封纯文本：ISBN 无法在入库时校验；提交时间无法可靠排序；多行链接与附件在转发中容易丢失；每条都要人工复制到数据库，重复劳动且容易漏。站内表单直接落 `note_submissions`，字段结构化、可校验、可筛选、可审计；邮件降级为「有新提交」的通知，由 `SUBMIT_NOTIFY=1` 控制，默认关闭（只写 `mail_outbox`，不投递）。

### 3.2 九项字段与校验

| # | 字段 | 必填 | 类型/上限 | 校验 |
|---|---|---|---|---|
| 1 | 日期时间 + 星期 | 否 | `datetime-local`，默认当前（Asia/Shanghai） | 合法日期时间；星期 0–6，前端按日期算出、可手改；默认当前时刻与星期 |
| 2 | 地点 | 否 | 文本 ≤80 | 去首尾空白，可空 |
| 3 | 天气 | 否 | 枚举 晴/多云/阴/雨/雪 + 温度 ≤8 | 枚举外一律置空；温度自由文本，仅长度限制 |
| 4 | 书名 + ISBN | 否 | 书名 ≤160；ISBN ≤20 | ISBN 为空通过；非空时去空格/连字符后必须通过 ISBN-10 或 ISBN-13 校验位，错误返回可读提示并保留输入 |
| 5 | 笔记标题 | **是** | ≤120 | 去空白后非空；唯一必填项 |
| 6 | 正文 | 否 | ≤20000 | Markdown；原始 HTML 转义；链接只允许 http/https |
| 7 | 思考/问题 | 否 | ≤280，单段 | 换行折叠为空格 |
| 8 | 颜色 / 小旗 | 否 | 枚举 | 颜色：无/杏/紫/靛/灰；旗：无/★/⚑/◆/●；仅作标记 |
| 9 | 相关链接 | 否 | ≤5 条，每条 ≤500 | 逐行解析；协议只允许 `http://` / `https://`，其余整条拒绝并提示 |

反滥用：同 IP 3 次/小时（`RateLimiter`，超出返回 429 + 可读页面并保留已填内容）；蜜罐 `website` 非空则静默丢弃并显示成功页；所有字段长度上限；轻量算术题（服务端随机两数，隐藏操作数，答案错误则回到表单）；CSRF 双提交令牌；不要求注册。

### 3.3 体验

- 单列、移动端优先；所有输入 `font-size:16px` 以上，避免 iOS 聚焦缩放；`scroll-margin-bottom` + `visualViewport` 增强，键盘弹出时把当前输入滚到可视区中部。
- 草稿：`localStorage` 键 `wh_reader_draft_v1`，输入防抖 400ms 保存；进入页面若本地有草稿且字段为空则恢复，并显示「已恢复草稿 · 清空」；提交成功后清除。
- 回执：`WH-YYYYMMDD-NNN`，按天流水，数据库唯一索引；成功页显示回执号 + 「审核后出现在读者笔记栏」。
- 校验失败：同页重渲染，保留全部已填内容并标出错误字段。

## 4. 数据模型

```sql
note_submissions(
  id, receipt UNIQUE, occurred_at, weekday, place, weather, temp_c,
  book_title, isbn, title, body, question, color, flag, links,
  lang, status, ip_hash, ip_region,
  created_at, reviewed_at, reviewer, reject_reason, review_note,
  note_id, original_json, edited_at, edited_by
)
-- status: pending | accepted | rejected
-- original_json：提交时的九项快照，只写不改
-- ip_hash：SHA-256 前 16 位；不存明文 IP
-- ip_region：粗略归属地（可开关，失败写「未知」）

reader_note_meta(
  note_id PK, submission_id UNIQUE, occurred_at, weekday, place, weather,
  temp_c, book_title, isbn, question, color, flag, links, created_at
)
-- 采纳后生成的正式笔记的九项信息；标题/正文在 note_i18n
```

采纳状态机：`pending --accept--> accepted`（生成 `notes(status=draft)` + `note_i18n` + `reader_note_meta`，写 `note_id`）；`pending --reject--> rejected`（记 `reject_reason`、`review_note`）。`accepted` / `rejected` 不可再改状态，只可查看与追溯。原始提交行与 `original_json` 永不覆盖；编辑只改当前字段并写审计。

公开可见性：采纳只生成**草稿**，前台不可见；站长在后台补译文/配图并发布后，才出现在 `/{lang}/reader-notes`。读者笔记与站长笔记、受邀读者文章三者在 SQL 层互斥：

- 站长笔记：`guest_author_id IS NULL AND NOT EXISTS(reader_note_meta)`
- 读者笔记：`EXISTS(reader_note_meta)`
- 受邀文章：`guest_author_id IS NOT NULL`

## 5. 审阅工作台（`/admin/review`）

- 默认进入「待审」，导航「审阅」带未读数；列表行：标题、提交时间、书名、粗略归属地、字数。
- 左列表 + 右详情（≥1000px 两栏；窄屏上下堆叠），详情直接渲染全文，不跳页。
- 就地编辑标题、正文、思考、书名等；保存/采纳时逐字段 diff 写 `audit_log`（字段名 + 旧值/新值，截断 120 字）。
- 一键采纳：生成 slug（ASCII 标题转写，否则 `reader-note-{id}`）、`notes` 草稿、`note_i18n`（提交语言）、`reader_note_meta`；提交行标记 accepted。
- 筛选：状态 tab、关键词（标题/正文/书名）、书名、日期区间；批量退回（复选框 + 原因）。
- 空状态：「今天没有待审」+ 说明；错误保留输入。
- 预览：编辑区下方「预览」面板，250ms 防抖调用 `POST /admin/review/preview`，用与前台完全相同的 `md::render` + 读者笔记版式渲染。

### 快捷键

| 键 | 动作 |
|---|---|
| `A` | 采纳当前条（含当前编辑内容），进入下一条 |
| `R` | 聚焦退回原因下拉；选好原因按 `Enter` 退回并下一条 |
| `J` | 下一条 |
| `K` | 上一条 |
| `Ctrl/⌘ + Enter` | 采纳并下一条 |

输入框内不拦截 `A/R/J/K`；`Ctrl/⌘+Enter` 在输入框内仍生效。

### 9.4 遗留风险

1. 列表筛选用 `LIKE`，数据量大时需要索引/全文检索；当前量级无影响。
2. `IP_GEO=1` 时依赖 ipinfo.io（2s 超时，失败留空），且只存国家/省/市，不存明文 IP。
3. 采纳只生成草稿；英文版标题为空时前台会显式提示并回退中文，需人工补译文。
4. 批量退回只处理 `pending`，已处理记录不可批量改判。
5. 375px 下页脚四栏堆叠高度约 915px，信息完整但较长。
6. 管理员单账号、无 2FA；登录限流 5 次/15 分钟，审计留痕。
7. 13 个编译警告（多为预留字段/未用导入）未清理，不影响运行。
8. 无外部监控告警，依赖 `journalctl -u wayhug-new`。
